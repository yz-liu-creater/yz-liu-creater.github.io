核心思想

一个预算，两种花法。

在固定的物理缓存预算下，下一个 K/V 条目既可以覆盖一个当前缺失的区域，也可以细化一个已经被表示的区域。GraceKV 把这两种选择放到同一尺度上直接比较。

购买覆盖范围

加入一个新区段

一个根原型，就能让某个层和 KV 头看到完整的上下文语义槽。

购买局部分辨率

细化已经覆盖的区域

一次 Split 用预先选定的子节点集合替换一个粗粒度原型，只在细节确实值得保留的位置增加条目。

1 组已存储 K/V 对 = 1 个物理预算单位
提示词 精确保留，不计入预算
可压缩的长上下文 共享的全局 Add/Split 竞价
近期窗口 精确保留，计入预算
问题与后缀 精确保留，不计入预算

压缩发生在一次标准预填充之后。GraceKV 复用这一遍前向中已经收集的 Q/K/V、采样隐藏状态、问题区域输出与 token 惊异度；不需要额外模型前向、不需要追加训练，也不会用掩码假装被删除的条目仍然存在。

不预设局部配额

在理解当前输入之前，不会先给各层、KV 头或语义槽切出固定份额。

随输入而变的分配

同一段文本在不同的层—KV 头组合中，可能需要不同的覆盖范围与局部分辨率。

全局竞争，贪心求解

“全局”只描述竞价的竞争范围覆盖所有候选位置，并不声称得到精确的组合全局最优解。

方法

结构向下展开，价值向上汇聚，预算追随效用。

GraceKV 先为覆盖范围和局部分辨率建立一套统一的结构表达，再估计当前输入真正需要什么，让每个可行的 Add 或 Split 用同一种物理单位参与竞争。

  1. 01划分找到连贯的语义槽
  2. 02表示构建原型树
  3. 03赋值追踪直接与间接证据
  4. 04分配全局排序 Add 与 Split
  5. 05打包写入物理不等长缓存

01 · 曲率引导的划分

在表征改变方向的位置切分。

GraceKV 把归一化隐藏状态看作一条沿 token 位置前进的轨迹。平滑区段可以共享更长的粗粒度表示；跨层、跨窗口尺度都稳定出现的转向，则更适合作为结构边界。

Token 惊异度提供较弱的辅助信号，动态规划还会同时考虑语义槽内部离散程度与合理长度。曲率决定的是在哪里合并在结构上更安全，而不是哪些内容对当前问题更重要。

结构决定在哪里切分，相关性决定在哪里花预算。

默认目标为每个语义槽约 64 个 token，并自适应约束在 16 至 128 个 token 之间。

02 · 渐进可细化表示

一棵树同时涵盖丢弃、合并与精确保留。

所有位置共享语义槽边界，但每个 (层, KV 头, 语义槽) 三元组都拥有自己的原型树。前沿是一组互不重叠的节点，它准确说明这个原子单元如何被存储。

  • 0 个条目：前沿为空，因此这个语义槽在物理缓存中不存在。
  • 1 个条目：根节点以粗粒度覆盖全部 8 个 token。
  • 3 个条目：选中的子区域获得更高局部分辨率。
  • 8 个条目：每个叶节点都保存其原始 token K/V。

一个已存储原型让整个语义槽仍可被寻址，但局部 token 细节会被合并。

单个缓存条目内部

原型要保留注意力行为，而不只是对向量求平均。

一个粗粒度节点用一条打包后的缓存表示一个连续区间。GraceKV 让这份打包表示与真正消费它的解码器保持一致。

键（Key）

逆旋转、求平均、再旋转

经过 RoPE 的键处在不同旋转坐标中。GraceKV 先将其逆旋转到同一坐标系，再求平均，最后在代表位置重新应用 RoPE。

值（Value）

让相关 token 拥有更大话语权

Value 按任务相关性加权，同时保留 10% 的均匀基线，使低价值背景信息也不会完全失去影响。

多重性

对不连贯的合并降权

键的一致性决定这个原型应当等效代表多少原始 token，避免平均得到的“幽灵键”获得被夸大的注意力质量。

03 · 自底向上的价值流

询问当前问题真正需要什么。

来自问题与序列尾部探针的直接注意力，可以识别显式证据；随后两轮 token 到 token 的传播会恢复间接依赖，例如问题本身没有强烈关注、但推理链必须经过的桥接实体。

Token 价值沿原型树向上求和。层—KV 头敏感度乘子刻画这一组件对模型输出的影响强弱。曲率和惊异度不会直接乘入相关性：它们塑造树的结构，而注意力证据为树节点定价。

精确信息保护

单例保底机制保护贪心步骤可能低估的事实。

姓名、数字、标签与少样本输出格式的收益可能并不平滑：抵达精确叶节点非常有用，但通往它的中间 Split 若逐步观察，可能显得没有那么值得。

因此，GraceKV 会在主竞价前，从高价值的 (层, KV 头, token) 叶节点中隔离出一个受预算上限约束的小集合。单例保底不免费、不在树外复制。

04 · 自顶向下的预算流

把所有可行的 Add 与 Split 放进同一个队列。

Add 比较的是完全丢弃与一个根节点覆盖；Split 比较的是父原型与更细的子节点集合。两者都按每个新增缓存条目的收益评分，因此早期层中的一次操作，可以直接与其他层、KV 头、语义槽或局部分辨率的操作竞争。这就是全局 Add/Split 竞价：全局指竞争范围，而非求得全局最优。

05 · 物理缓存打包

只写入竞价胜出的前沿节点。

每个层—KV 头组合都会得到独立长度的不等长缓存。未被选中的根节点不产生条目；内部节点存储打包原型；单例节点存储原始 K/V。新生成的 token 以多重性 1 追加。

当预算恢复到 FullKV 规模时，每棵树都可以展开到 token 叶节点，并精确恢复原始上下文条目。

技术细节与默认设置

语义槽构建。多层、多尺度曲率在采样深度与窗口之间做稳定化；惊异度是较弱的辅助边界信号。默认语义槽长度为 16–128 个 token，目标为 64。

价值流。问题与序列尾部探针提供直接相关性的种子；默认权重 0.3 的两次图传播恢复间接证据。父节点价值等于子节点价值之和。

原型保真度。基于探针的失真以 0.25:0.75 加权注意力分布误差与 Value 聚合误差。构树时会同时考虑高曲率候选切分点和区间中点，也可以用三路子节点集合隔离一个显著 token。

单例保底机制。默认上限是可分配基础预算的 0.6，但这是硬上限，并不保证一定花掉 60%。每个最终实现的单例都要支付完整树路径成本。

效果与现实意义

预算越紧，灵活分配的缓存越能保持用途。

核心结果不只是某一个基准上的孤立胜利。GraceKV 在需求相反的任务之间都保持竞争力：摘要与聚合需要广泛的覆盖范围，问答与检索则需要锐利的局部可寻址性。

20 / 24 LongBench 的 24 个设置中有 20 个排名第一，其余 4 个排名第二
24 / 32 在 Qwen2.5-7B 的 LongBench + RULER 任务—预算组合中排名第一
128× LongBench 中评估的最高压缩率；这是压力测试，而不是无损声明
摘要 让整篇文档始终在视野中

广泛但较低的局部分辨率，可以避免整个主题或章节完全消失。

在统一的固定缓存贪心解码器下，GraceKV 与 FullKV 通常都处在 23–25 ms/token。同一方法在不同数据集上可能稍快或稍慢，因此最稳健的结论是显存下降，速度收益仍取决于 kernel 与 workload。

它在现实中可能改变什么

GraceKV 能在固定显存上限下创造余量。

节省下来的 KV 缓存字节，可能支持更长的可服务上下文或更大批次。这些是部署层面的含义，而不是端到端服务测量；最终收益还取决于模型权重、激活、显存碎片与调度器。

文档助手 让更多原始材料常驻显存

更小的缓存可以让一份长报告、合同或论文集合中的更多内容常驻，同时不强迫每个章节获得相同局部分辨率。从同一份完整预填充状态重复生成，还可以摊薄构建成本。

智能体与代码系统 在长历史中保留精确标识符

代码仓库上下文、工具轨迹、实体名、数字与输出格式，把大量背景和少数精确事实混合在一起，恰好对应方法对覆盖范围与局部分辨率的联合分配。

多用户服务 创造潜在的批次或并发余量

当 KV 显存限制请求准入时，更小的物理缓存可能让系统在设备上保留更多会话，或减少驱逐、卸载缓存的压力。论文并未端到端测量这一行为。

权衡不够有利的场景 短请求、一次性请求或计算受限请求

如果生成很短、上下文很小，或注意力不受显存带宽限制，那么秒级的一次性构建成本可能超过稳态节省。因此论文将显存容量视为近期最主要的系统收益。
